# 语音带宽扩展（22.05 kHz → 48 kHz）选型与验证

- **日期**: 2026-10-31
- **结论落地**: [`specs/itts-timestamps-and-hifi-design.md`](../../specs/itts-timestamps-and-hifi-design.md) §6，代码 `crates/core/src/models/bwe.rs`
- **硬件**: Apple M5 Pro

## 1. 为什么不能直接输出 44.1/48 kHz

CFM 生成的是 22.05 kHz、80 band 的 mel（n_fft 1024、hop 256），BigVGAN（22k/80band/256x）据此只能还原到 22.05 kHz，内容上限 11.025 kHz。直接重采样不会增加任何内容。真正提高带宽只有三条路：

| 路线 | 结论 |
|------|------|
| 换一个"22k mel → 44.1/48k"的声码器 | 不存在现成权重。最接近的是用 `nvidia/bigvgan_v2_44khz_128band_512x`（MIT，122M）加 80-band 输入层微调——它的帧率 44100/512 = 86.13 fps 恰好等于 IndexTTS mel 帧率，但这是训练项目 |
| 重训 S2Mel 到 44.1k mel | 训练项目，超出范围 |
| **在 22.05k 输出上做带宽扩展（BWE）** | **采用** |

上游 IndexTTS 只提供 22.05 kHz：issue #89 维护者答复"重采样即可"，#315 社区建议 AP-BWE，#714 无回复。

## 2. 候选模型

| 模型 | 类型 | 参数 | 输入 → 输出 | 许可（代码/权重） | 公开指标（VCTK） | 移植难度 |
|------|------|------|-------------|-------------------|------------------|----------|
| **LavaSR v2**（arXiv 2603.07285，2026-03） | Vocos GAN，单次前向 | ~14M | 任意 8–48k → 48k | Apache-2.0 / Apache-2.0 | 24→48k LSD 0.63（AP-BWE 0.64） | 低：Conv1d、LN、Linear、GELU、iSTFT |
| AP-BWE（arXiv 2401.06387） | GAN，单次前向 | ~29.8M | 每种输入率一个 checkpoint → 48k | MIT / MIT | 24→48k LSD 0.61，ViSQOL 4.25 | 低到中；帧率为 LavaSR 的 13 倍；会重生成低频相位；权重在 Google Drive |
| FlashSR | 1 步蒸馏潜扩散 | ~638M | → 48k | 权重疑为 CC-BY-NC | — | 大且非商用 |
| AudioSR | 潜扩散 ~50 步 | 258M | → 48k | 许可存在冲突 | LSD 1.4–1.6 | 不值得 |
| MossFormer2-SR | Transformer + GAN | ~110M | → 48k | Apache-2.0 | LSD 0.82 | 难 |
| NovaSR | GAN | 极小 | 仅 16k → 48k | Apache-2.0 | 低于 LavaSR | 16k 输入会丢掉 8–11 kHz |

选择 **LavaSR v2**：最小的强 GAN、质量与 AP-BWE 持平、许可宽松、算子几乎全部已在本仓库（codec 的 ConvNeXt、realfft）。风险：只在 VCTK（约 44 h 英文朗读）上训练，单作者项目、无训练代码、无 MOS。

## 3. 权重来源与可信度

- 官方仓库 `YatharthS/LavaSR` 只有 torch pickle（`enhancer_v2/pytorch_model.bin`）。为避免在 Rust 中解析 pickle，使用第三方 safetensors 转换 `AEmotionStudio/lavasr-models@291b7810dcd42e111b114fcc6cf07d0d021b9bea`。
- 验证：用 torch 加载官方 `.bin` 与该 safetensors，**83 个张量键、形状、dtype、数值逐位一致**；两边 `config.yaml` 字节相同。
- 运行时固定 revision，并在加载前校验文件 BLAKE3（`e104610625b3a16b05f88dad36a26b7c47e7554c15011da64331988bba1007e2`），不一致即拒绝加载。
- checkpoint 自带 mel 滤波器组（`feature_extractor.mel_spec.mel_scale.fb`，1025×80）和两个 Hann 窗，直接使用，避免重算偏差。

## 4. 移植要点（与参考实现的差异）

```text
22.05k → sinc 重采样 48k → 两端反射填充 768 → |STFT|（n_fft 2048、hop 512、Hann、不居中）
 → fb 投影 → log(max(x, 1e-5)) → Conv1d(k7) → LN → 8×ConvNeXt(512/1536) → LN
 → Linear(512→2050) → min(exp(mag), 1e3)、相位 → iSTFT（OLA ÷ 窗平方包络，裁掉两端 768）
 → 全长 rFFT 交叉合并 → 48k
```

- **输入路径**：参考实现无论输入率都先降到 16 kHz（会丢掉 8–11 kHz），我们直接 22.05k → 48k。
- **交叉合并**：参考实现按"bin 数"定义过渡带（宽度随信号长度变化）；我们按 Hz 定义，长度无关。
- **交叉频点**：原生信号从约 10 kHz 起就开始滚降（BigVGAN 与重采样器边缘衰减，10.5–11k 已到 −58.7 dB），而模型预测在 10–12 kHz 平滑连续。扫描结果（相对总能量）：

| 交叉中心/宽度 | 9–10k | 10–10.5k | 10.5–11k | 11–12k |
|---------------|-------|----------|----------|--------|
| 原生（上采样） | −38.4 | −47.4 | −58.7 | — |
| 10.5k / 1k | −38.4 | −48.5 | −50.3 | −47.2 |
| **10.0k / 1k** | −38.6 | −47.5 | −48.6 | −47.2 |
| 9.0k / 2k | −41.3 | −45.7 | −48.6 | −47.2 |

  取 **10 kHz ± 0.5 kHz**：9.5 kHz 以下逐 bin 保留原始信号，10–11 kHz 不出现凹陷。

## 5. 验证结果

- **数值一致性**：同一 22.05k WAV 分别经 Rust 实现与"官方 vocos 代码 + LavaSR head 补丁"的参考实现：全信号 SNR **73.0 dB**，>11 kHz 生成频带 SNR **36.2 dB**（GPU float32 经 `exp` 的正常误差）。
- **低频保留**：模型测试逐 bin 校验生成段内 9.5 kHz 以下与原始信号相对能量差 < 1e-9。
- **频谱**：与同一说话人的真实 48 kHz 录音对比（相对总能量，dB）：

| 频段 | 原生 22k | 扩展 48k | 真实录音 |
|------|----------|----------|----------|
| 8–10k | −33.8 | −34.7 | −32.9 |
| 10–11k | −43.6 | −45.0 | −40.9 |
| 11–12k | −98.1 | −47.2 | −46.0 |
| 12–14k | — | −46.3 | −48.0 |
| 14–16k | — | −50.6 | −56.1 |
| 16–20k | — | −50.9 | −61.9 |
| 20–24k | — | −54.9 | −68.5 |

  11–14 kHz 与真实录音几乎一致；14 kHz 以上比真实录音亮 5–14 dB。
- **性能**：7.66 s 音频扩展耗时 34 ms（RTF 0.004）；进程内第一次调用约 0.65 s（Metal 内核编译 + FFT 规划），daemon 中只发生一次。
- **时长与时间戳**：输出长度严格等于 22.05k→48k 重采样长度；对齐在原生音频上完成，不受影响。

## 6. 局限与后续

- 只在 VCTK 英文上训练；中文、情绪化语音、不同音色下的主观质量需要人工 A/B 试听。默认仍为 22.05 kHz，48 kHz 按请求启用。
- 14 kHz 以上能量偏高，若试听觉得"嘶"，可在交叉合并后对 >14 kHz 加一个缓坡（如 −3 dB/oct）——需听感数据支撑后再做。
- 若 LavaSR 在某些音色上不稳定，备选是 AP-BWE 24k→48k（MIT），同样包一层交叉合并。
